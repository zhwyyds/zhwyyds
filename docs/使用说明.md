# 数据治理平台 — 使用说明

> 版本：1.0 ｜ 日期：2026-08-05 ｜ 面向：数据治理人员（指标维护/审核/发布）
> 配套：《运维手册》docs/运维手册.md（环境与排障）｜ 平台地址：http://127.0.0.1:8765/

---

## 一、平台能做什么（一句话）

从「含糊的指标定义」到「可发布的精准指标」的全流程治理平台：
**词根 → 指标 → AI 起草口径 → 人工核查 → 六维评分 → 按域发布**，全程文件存储、人只做核查与决策。

## 二、登录与界面

1. 启动服务：`data-governance serve --port 8765`
2. 浏览器打开 `http://127.0.0.1:8765/`
3. 左侧导航 13 个页面：治理总览 / 指标库 / 指标管理 / 词根库 / 批量生成 / 模型评审 / 字段血缘 / 表血缘 / 命名规范 / 口径治理 / 评分看板 / **口径核查**（迭代 2 新增）

## 三、核心操作流程

### 1. 维护词根库（基础字典）

- 词根 = 命名的最小单元（如「订单 order」）。**新建**：词根库 → 「+ 新增词根」→ 填 中文名/英文名/缩写/类型/所属域 → 创建（自动分配 `R_{域}_{序号}`）。
- **编辑**：列表行「编辑」→ 修改说明等 → 保存。
- 校验：`data-governance validate` 会检查词根必填字段与重复。

### 2. 新建指标（原子指标）

指标管理 → 新增 → 填 中文名/英文名/缩写/类型(atomic)/所属域/口径。**英文名必须规范**（小写下划线，可拆解为已注册词根），残留拼音会触发评分封顶 B。

### 3. 批量生成派生指标（⭐ 从 1 个变 N 个）

批量生成页：
1. **Step 1** 勾选原子指标（自动列出所有 atomic 类型指标）
2. **Step 2** 勾选修饰词（本月/本年/环比/同比…，来自 `config/modifier_rules.csv`）
3. 「🔄 刷新预览」→ dry-run 预览生成的派生指标（不写库）
4. 「⚡ 一键生成」→ 写入指标库（幂等：已存在的英文名自动跳过）

> 例：订单金额 × [本月, 本年] → `mtd_ord_amt 本月订单金额`、`ytd_ord_amt 本年订单金额`。
> 新生成指标进入**口径核查队列**（自动待核查）。

### 4. 口径核查（⭐ AI 起草，人只做核查）

口径核查页（nav「口径核查」）：
- **待核查队列**：列出所有 `pending/rejected` 的指标，展示 AI 推荐的业务定义/统计周期/边界条件与起草模型。
- **批准**：确认无误 → 批准 → 写入正式口径 + **自动重新评分**。
- **打回**：需填原因 → 回到队列（原因会显示）。
- **存量补全**：一键对未起草口径的存量指标批量 AI 起草。

> 口径起草由 3 个大模型并行完成、字段级共识汇总；`caliber_business` 三模型分歧或 ≥2 个字段分歧会标记高风险。Mock 模式（无 Key）用于演示，配置 Key 后自动 live。

### 5. 模型评审（多模型比对）

指标管理/指标库 → 指标 → 「发起评审」：3 个模型对命名/口径打分与挑问题，汇总共识结论（`model_consensus`）。评审通过 → 指标 `review_status = approved`。

### 6. 查看评分（六维度明细）

评分看板 / 指标详情 → 评分：命名规范 / 词根关联 / 口径完整 / 同名同义 / 血缘可查 / 模型评审，总分 100 + 等级 S/A/B/C/D。
- 特殊规则：**拼音残留封顶 B、口径为空封顶 C**
- 批准口径后重评分，等级变化实时可见

### 7. 发布与撤销（按域版本控制）

- **发布**：指标管理 → 域操作「发布本域」→ 自动分配版本 `v{n}`（该域所有 `approved` 指标批量发布）。
- **发布门禁**：口径未核查（pending/rejected）的指标**禁止发布**；已发布版本不回滚。
- **撤销**（API）：`POST /api/domains/{域}/revert {"version": 2}` → 指标回退上一版本 + 历史留痕。
- **版本对比**（API）：`GET /api/domains/sale/version-diff?from=v1&to=v2` 查看两版本指标差异。

### 8. 血缘管理

- **上传**（API）：`POST /api/lineage/upload`，JSON 结构校验后写入 `lineage/{域}_lineage.json`。
- 查看：字段血缘 / 表血缘页。

### 9. 项目验收自检

- `data-governance validate`：一键体检（编码/字段数/必填/重复/词根引用/域归属/血缘 JSON），有 error 时退出码 1。
- `data-governance acceptance run`：按《验收评分标准.md》生成 14 域验收报告（scoring/acceptance_report_日期.md）。
- 域级红绿灯（API）：`GET /api/dashboard/domains`（词根/指标/评分/血缘/口径/发布）。

## 四、演示数据

```bash
python scripts/demo_data.py   # 生成 S/A/B/C 四级演示指标（含拼音残留/口径空反例）
```

生成后即可在 口径核查（AI 起草）→ 评分看板 完整演示「起草→核查→评分→发布」链路。

## 五、常用命令速查

```bash
data-governance serve --port 8765                              # 启动平台
data-governance validate                                       # 数据自检
data-governance metric generate --domain sale --atomics M_SALE_001 --modifiers T001,T002 --write   # 批量生成
data-governance metric review --domain sale --input examples/metric_review_sale.json               # 多模型评审
data-governance acceptance run                                  # 验收报告
python scripts/demo_data.py                                     # 演示数据
scripts/backup.sh                                               # 每日备份
```

## 六、常见问题

| 问题 | 处理 |
|---|---|
| 评审一直走 Mock，没用真模型 | 配置 Key（见运维手册 §3），`GET /api/llm/status` 查看模式 |
| 批量生成没反应 | 先确认勾选了原子指标和修饰词；原子指标需 `metric_type=atomic` |
| 发布报「口径未核查」 | 先去口径核查页批准/修改该指标口径 |
| 指标评分等级 B/C 上不去 | 看评分明细：拼音残留 → 改英文名；口径空 → 用口径助手起草后批准 |
| 数据疑似被改坏 | `data-governance validate` 定位 → 从 `backup/` 或 git 历史恢复 |
