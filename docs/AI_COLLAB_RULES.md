# AI 协作铁律（约束文件）

> 本文件是项目硬约束。**任何 AI 助手 / 开发者在本项目改动 UI / 交互 / 业务流程时，必须遵守下列规则。**
> 制定依据：2026-08-07 一次 UI 交互（peek 行为）反复返工 4 次的真实教训。

---

## 一、用户需求交互的"三个禁止"

1. **禁止自作主张加东西** —— 用户描述的需求是上限，不是下限。用户说"上移"，就只做上移；不要顺手加放大、发光、变暗、变透明、z 提升、让位动效。
2. **禁止把"用户描述需求"当成"动手许可"** —— 用户描述完不等于确认开始改。用户没明确说"对/可以改/动吧"之前，不动代码。
3. **禁止光说不做** —— 用户指出问题（包括复盘后），必须立即动手改；不要只承认不复盘不修改。

---

## 二、修改 UI / 交互的标准流程（强制）

任何 UI / 交互改动，**必须**按此顺序：

1. **复述理解** —— 用文字/示意图/列表，把你认为的用户需求写出来
2. **画示意图确认** —— 用户原话含"画""重画""示意"时，必须画 SVG/图示给用户看（用 `show_widget`）
3. **等用户明确回复"对"** —— 没有"对/OK/改吧"之前，不动代码
4. **改一处、复述改动** —— 改完说明"改了什么/为什么/影响"，让用户验收
5. **用户验收前不继续** —— 用户没说"通过"，就不开始下一处

> **反例**：用户说"重新画一版"= 画图确认；用户说"你改吧"= 动手许可；用户说"对"= 当前理解正确。

---

## 三、需求理解有歧义时

- **画图 + 文字复述**，让用户用他自己的话确认/纠正
- **不要用 AskUserQuestion 当"确认"** —— 用户跳过选项 = 不回答，不等于同意
- **不要把球推给用户**（"你选""停还是继续"）—— 用户疲惫时这是甩锅
- 如果用户表达模糊（"不太对"），**默认改回更保守的方案**，不要加戏

---

## 四、peek 类交互的硬规则（本项目特定）

针对指标卡组件的 hover/peek 行为，**永远遵守**：

1. hover 卡：**只做 `translateY`**，不上 scale、不改 z-index、不发光、不变暗、不变透明
2. 邻卡：**位置/透明度/z 序全部不变**，不允许变暗让位、不允许左右分开让位
3. 压着关系：hover 前后保持一致
4. 卡面：**实心**，不允许半透明叠加层让卡面看起来透明

---

## 五、情绪与节奏

- 用户连续返工 ≥2 次后：**自动暂停、复盘、画图确认**，不再继续猜
- 用户愤怒时（骂人）：**不辩解、不甩锅、不转移话题**；承认问题 → 立刻行动
- 不要在复盘时说漂亮话（"我会改好""以后一定"）—— 用实际改代码证明

---

## 六、复盘归档（教训清单，每次重大失误后补充）

### 2026-08-07：peek 交互反复返工 4 次

**用户原始需求（一句话）**：hover 时，卡片整体向上移动露出名称；其他卡片全部保持原样。

**我的实际做了什么**（4 次提交）：
1. 第 1 版：translateY(-10px) ✓ 方向对，但幅度太小+后续被插画区等"加戏"
2. 第 2 版：邻卡 opacity 0.35 变暗让位 → **用户没要**
3. 第 3 版（撤回后）：重画示意图 = 画图给用户确认 → 我跳过，直接改
4. 第 4 版：加 z-index:2 让 hover 卡盖邻卡 → 违背"压着关系不变"
5. 加上"稀有度氛围色调"+斜纹 → 卡面看起来透明

**核心错误**：每次我都在"上移"之外加东西；用户每次纠正，我又换一个花样加。每次都是我没画图确认就动手。

**正确做法（一句话）**：画示意图给用户确认 → 用户说"对" → 只做 translateY(-30px)，什么都不加。
