# 数据治理平台 — 运维手册

> 版本：1.0 ｜ 日期：2026-08-05 ｜ 适用：本地运行模式
> 配套：`scripts/backup.sh`（备份）、`data-governance validate`（自检）

---

## 1. 环境准备

```bash
cd /Users/heyuan/DEVELOPMENT/data_go
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev,api]"
```

- Python ≥ 3.10（推荐 3.11+）
- 数据以文件存储：`config/ roots/ metrics/ lineage/ reviews/`，**无需数据库**

## 2. 启动 / 停止

### 启动 Web 服务（含治理 UI + OpenAPI）

```bash
data-governance serve --port 8765
# http://127.0.0.1:8765/        治理 UI
# http://127.0.0.1:8765/docs     OpenAPI 文档
```

停止：`Ctrl+C`。

### CLI 常用命令

```bash
data-governance version                          # 版本
data-governance validate                         # 数据自检（有 error 时 exit 1）
data-governance acceptance run                   # 生成验收报告
data-governance root generate --domain cust --input examples/root_generation_cust.json   # 词根生成
data-governance metric review --domain sale --input examples/metric_review_sale.json      # 指标评审
```

## 3. LLM Key 配置与模式切换

| 模式 | 说明 |
|---|---|
| `mock` | 内置假数据，开发/演示用，无需 Key |
| `live` | 真实调用大模型（OpenAI / Anthropic / 千问），`config/models.csv` 中 ≥2 个模型配好 Key 才启用并行比对 |
| `auto`（默认） | 有 Key 则 live，否则 mock |

**配置 Key（二选一）：**

```bash
cp .env.example .env      # 编辑：OPENAI_API_KEY=sk-...、ANTHROPIC_API_KEY=...、DASHSCOPE_API_KEY=...
# 或
cp config/secrets.example.json config/secrets.json   # 编辑对应字段
```

**查看当前模式：** `GET /api/llm/status`（不返回密钥本身）。

> ⚠️ Key 已加入 `.gitignore`，不会入库；本地注意文件权限（`chmod 600 .env config/secrets.json`）。

## 4. 备份与恢复

**每日备份（建议 cron）：**

```bash
# crontab -e 添加：
# 0 2 * * * cd /Users/heyuan/DEVELOPMENT/data_go && ./scripts/backup.sh >> backup/backup.log 2>&1
```

手动备份：`scripts/backup.sh`（默认保留最近 7 天，`KEEP_DAYS=14` 可调）。

**恢复：** 将 `backup/<时间戳>/` 下对应目录复制回项目根即可：

```bash
cp -R backup/2026-08-05_120000/metrics ./metrics
```

**兜底：** 项目已上 git（origin 为 GitHub SSH），核心代码与数据文件随提交留痕。

## 5. 数据自检

`data-governance validate` 一键体检：UTF-8 编码 / 字段数 / 必填字段 / 重复 ID / 指标词根引用完整性 / 域归属 / 血缘 JSON。

- 无 error：`exit 0`（warning 仅为提示，如缺域文件）
- 有 error：`exit 1`，逐条列出问题

**发现 CSV 被手改坏时**：用最近一次备份恢复该文件，或从 git 历史找回（`git log -- <文件>`）。

## 6. 常见问题排查

| 现象 | 排查 | 处理 |
|---|---|---|
| 端口被占用（`Address already in use`） | `lsof -i :8765` | 换端口 `--port 8766` 或杀旧进程 |
| 评审一直用 mock，Key 没生效 | `GET /api/llm/status` 看 mode | 确认 `.env`/`secrets.json` 存在且 `models.csv` 的 `api_key_env` 对应 |
| CSV 乱码/字段错位 | `data-governance validate` | 恢复备份或按 header 修正 |
| 血缘页空白 | `lineage/` 下是否有 `*_lineage.json` | 检查文件命名 `{domain}_lineage.json` 与 JSON 可解析性 |
| 服务启动即报错 | `data-governance validate` + 看日志 | 按第 7 节收集日志 |
| 推送 GitHub 失败 | 见"远程"一节 | 确认 SSH 公钥已加 GitHub |

**日志位置：**
- 服务日志：启动终端 stdout/stderr；后台运行建议重定向：`data-governance serve --port 8765 >> /tmp/dg.log 2>&1`
- 应用日志：当前版本无独立日志文件，业务留痕见 `releases/*_releases.json`（发布历史）、`scores/_summary.csv`（评分历史）
