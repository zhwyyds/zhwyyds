## 1. 系统架构

```
┌─────────────────────────────────────────────┐
│  浏览器  →  http://127.0.0.1:8080           │  ← ui-prototype/（静态页）
│                 │  fetch (CORS)             │
│                 ▼                           │
│  FastAPI  →  http://127.0.0.1:8765          │  ← src/data_governance（API）
│                 │                           │
│                 ▼                           │
│  文件存储：CSV/JSON（metrics/ roots/        │  ← 数据层（不上库）
│           reviews/ lineage/ scores/ config/ │
└─────────────────────────────────────────────┘
```

- **前后端分离部署**：静态页（8080）+ API（8765）独立进程
- **数据存文件**：无数据库，CSV/JSON 直接读写（fcntl 文件锁防并发）
- **LLM**：多模型比对（DeepSeek/OpenAI/Claude/通义/智谱），无 Key 自动降级 Mock

## 2. 启动 / 停止

### 2.1 一键启动（开发机）

```bash
# 终端 1：启动 API（8765）
export PYTHONPATH=src
.venv/bin/python -m data_governance.cli serve --host 127.0.0.1 --port 8765

# 终端 2：启动静态页（8080）
cd ui-prototype
python3 -m http.server 8080

# 浏览器访问
open http://127.0.0.1:8080
```

### 2.2 CLI 子命令一览

```bash
python -m data_governance.cli version            # 版本
python -m data_governance.cli serve [--port 8765] [--base-dir PATH]
python -m data_governance.cli validate [--base-dir PATH]   # 数据自检
python -m data_governance.cli root generate      # 词根多模型生成
python -m data_governance.cli metric review      # 指标多模型评审
python -m data_governance.cli metric generate    # 批量生成派生指标
python -m data_governance.cli acceptance run     # 验收评分
```

### 2.3 停止

```bash
# 按端口杀进程（注意：精确匹配，勿误杀其他服务）
lsof -ti :8765 | xargs kill -9   # API
lsof -ti :8080 | xargs kill -9   # 静态页
```

## 3. 环境变量

| 变量 | 用途 | 缺省 |
|---|---|---|
| `DEEPSEEK_API_KEY` / `DATA_GOV_DEEPSEEK_API_KEY` | DeepSeek LLM | 无 → 该模型降级 |
| `OPENAI_API_KEY` | OpenAI | 无 → 该模型降级 |
| `ANTHROPIC_API_KEY` | Claude | 无 → 该模型降级 |
| `DASHSCOPE_API_KEY` / `QWEN_API_KEY` | 通义千问 | 无 → 该模型降级 |
| `ZHIPUAI_API_KEY` / `GLM_API_KEY` | 智谱 | 无 → 该模型降级 |
| `DATA_GOV_BASE_DIR` | 数据根目录（serve 自动设置） | 仓库根 |

> **全部缺 Key 时自动进入 Mock 模式**：AI 功能仍可用（返回样例），适合演示/开发。
> 真实评审需要至少 1 个有效 Key。建议配置多个实现"多模型比对"。

## 4. 数据目录与备份

### 4.1 数据目录职责

| 目录 | 内容 | 变更来源 |
|---|---|---|
| `metrics/` | 指标 CSV（按主题域分文件） | 前端新增/编辑/批量/生成 |
| `roots/` | 词根 CSV | 词根管理/AI 生成 |
| `reviews/` | 多模型评审 JSON | 指标评审 |
| `lineage/` | 血缘 JSON | 血缘上传 |
| `scores/` | 评分 JSON/CSV | 评分引擎 |
| `config/` | 域名/树/模型/修饰词配置 | 手工维护 |
| `releases/` | 发布记录 | 发布/下线 |

### 4.2 每日备份（IT1-3）

```bash
# 手动备份（默认保留 7 天）
scripts/backup.sh

# 保留 14 天
KEEP_DAYS=14 scripts/backup.sh

# 指定项目根
scripts/backup.sh /path/to/data_go
```

备份到 `backup/YYYY-MM-DD_HHMMSS/`，自动清理过期。

**配置定时备份（macOS launchd / Linux cron）：**

```bash
# Linux crontab：每天 02:30
30 2 * * * /bin/bash /path/to/data_go/scripts/backup.sh /path/to/data_go >> /var/log/data_go_backup.log 2>&1
```

### 4.3 恢复

```bash
# 把备份目录内容复制回项目根（示例恢复 metrics）
cp -R backup/2026-08-06_150841/metrics ./metrics
```

## 5. 数据自检（validate）

```bash
python -m data_governance.cli validate
```

检查项：字段数对齐、必填缺失、重复 ID、词根引用、主题域合法性、血缘 JSON 可解析。
返回码 `0` = 无 error；`1` = 有 error。CI / 定时任务可用返回码做门禁。

## 7. 常见故障排查

| 现象 | 排查步骤 |
|---|---|
| 页面 502 / 打不开 | `lsof -ti :8080` 看进程是否存活；kill 后重启 `python3 -m http.server 8080` |
| 前端 AI 生成无反应 | ① `curl 127.0.0.1:8765/health` 确认 API 活着 ② 检查浏览器 Network 是否有 404/跨域报错 ③ 确认 8080 页面 → 8765 API 的 CORS/API_BASE 探测正常（前端自动回退 8765） |
| 评审/生成报错 "Failed to fetch" | API 进程挂了或 LLM Key 失效；看 API 终端日志；重启 serve |
| 页面出现原生弹窗 | 属遗留 bug，按 `docs/development-playbook.md` §4.5 修复（禁 alert 用 toast） |
| 数据改了不生效 | CSV 文件锁可能残留：`ls metrics/*.lock`，确认无异常进程后删除 `.lock` |
| 测试全绿但前端坏 | 前端改动未过 Playwright 冒烟：跑 `tests/e2e/test_frontend_smoke.py`（须 8080/8765 已启动） |

## 9. 安全注意事项

- API 无内置鉴权中间件时仅限本机/内网访问，勿暴露公网（生产环境需加 API Key 认证或网关）
- LLM Key 属于敏感信息：建议存 shell profile / 密钥管理，勿提交到仓库（`.gitignore` 已含 `.env`）
- 删除指标为物理删除（有确认弹窗 + 日志），操作前建议先备份
