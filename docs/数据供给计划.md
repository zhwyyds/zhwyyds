## 二、数据灌入路线（三阶段）

### 阶段 A：试点域（sale）跑通全链路 —— 本周
- **目标**：sale 域 50+ 指标、全链路（生成→起草→核查→评分→发布）演示通过
- **动作**：
  1. sale 词根补到 15+（人工 + `POST /api/roots` 维护）
  2. 定义 8-10 个原子指标（含 1-2 个反例演示）
  3. 批量生成派生（`POST /api/metrics/batch-generate`）
  4. 口径助手起草 + 人工核查（口径核查页）
  5. 多模型评审 → 发布 v1
- **产出**：sale 域验收 6 维度达标示范 + 演示素材

### 阶段 B：全 14 域铺开 —— 两周
- **目标**：14 域均有词根库、指标库、血缘文件
- **动作**（按域批量执行，工具链已就绪）：
  1. 每域从多源系统归集清单 → 人工/LLM 梳理词根（`root generate`）
  2. 原子指标定义（每域 8-15 个）→ 批量生成派生
  3. 血缘文件（外部解析器输出 → `POST /api/lineage/upload`）
  4. 口径全量补全（`/api/caliber/backfill`）+ 核查
- **责任人**：每域 owner（见下节认领表）

### 阶段 C：验收冲刺 —— 验收前 1 周
- **目标**：数据到位 + 验收报告达标
- **动作**：
  1. `data-governance validate` 0 error
  2. `data-governance acceptance run` 逐域过关（词根覆盖/命名/同名同义/口径/血缘/评审）
  3. 域级看板（`/api/dashboard/domains`）全绿
  4. 黄金演示数据（`scripts/demo_data.py`）备好
