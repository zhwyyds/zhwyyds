# 口径字段标准与迁移方案（IT1-6 定稿）

> 版本：1.0 ｜ 日期：2026-08-05 ｜ 上游需求：《AI口径定义助手需求与迭代计划.md》
> 本文件为迭代 2「口径助手」开发的字段契约与迁移依据

---

## 1. 新增字段定义（追加到 metrics CSV）

在 `METRIC_CSV_FIELDS` 尾部追加以下 12 列：

| 列名 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `caliber_business` | str | 条件必填 | `""` | 业务定义（是什么） |
| `caliber_formula` | str | 否 | `""` | 计算公式 |
| `caliber_period` | str | 否 | `""` | 统计周期（月/周/日/季/年…） |
| `caliber_granularity` | str | 否 | `""` | 计算粒度（订单行级…） |
| `caliber_boundary` | str | 否 | `""` | 边界/排除条件 |
| `caliber_source` | str | 否 | `""` | 来源表/字段 |
| `caliber_owner` | str | 否 | `""` | 口径责任人（人核查时确认） |
| `caliber_status` | str | 是 | `""` | 核查状态：`""`(未起草) / `pending` / `approved` / `edited` / `rejected` |
| `caliber_ai_by` | str | 否 | `""` | 起草模型列表 + 共识标记，如 `gpt-4o;claude-3.5-sonnet;qwen-plus(consensus)` |
| `caliber_checked_by` | str | 否 | `""` | 核查人 |
| `caliber_checked_at` | str | 否 | `""` | 核查时间 ISO（YYYY-MM-DD HH:MM） |
| `caliber_reject_reason` | str | 否 | `""` | 打回原因（rejected 时记录） |

**必填规则**：`caliber_status == approved/edited` 时，`caliber_business` 必须非空（发布门禁强制）。

## 2. 兼容策略

| 项 | 策略 |
|---|---|
| `caliber_desc`（旧列） | **保留**，作为结构化字段的汇总视图：迁移脚本按 `caliber_business + 统计周期 + 计算公式` 拼接生成，保证现有评分/导出/展示逻辑零改动 |
| `tech_caliber` | 不动（技术口径仍人工维护） |
| 存量数据 | 迁移脚本补列，`caliber_status` 置 `""`（未起草）；有 `caliber_desc` 的存量指标进入「存量补全」候选，由口径助手一键起草 |

## 3. 状态机

```
"" (未起草) ── 起草 ──> pending ──┬── 批准 ──> approved（写正式字段 + 触发重评分）
                                  ├── 修改 ──> edited（人工改后视为 approved 等效）
                                  └── 打回 ──> rejected（附原因）── 重起草 ──> pending
```

**发布门禁（迭代 3 落地）**：`caliber_status ∉ {approved, edited}` 的指标禁止发布；历史已发布版本不回滚。

## 4. 迁移方案

**脚本**：`scripts/migrate_caliber.py [--base-dir X] [--dry-run]`

1. 遍历所有 `*_metrics.csv`：
   - 若 header 缺新增 12 列 → 追加列（空值）
   - 对 `caliber_desc` 非空且 `caliber_status == ""` 的行：置 `caliber_status = "pending"`，标记待核查/补全
2. 同步更新 `METRIC_CSV_FIELDS`（代码先行）与 `MetricRecord` dataclass
3. `--dry-run` 只输出将变更的行数，不写盘

**验证**：迁移后跑 `data-governance validate` + `pytest`，确认无回归。

## 5. API 契约草案（迭代 2 实现）

| 方法 | 路径 | 说明 | 关键响应字段 |
|---|---|---|---|
| POST | `/api/metrics/{id}/caliber/draft` | 触发多模型起草（mock/live） | `{metric_id, status:"pending", caliber:{...}, diff_summary:[...]}` |
| GET | `/api/caliber/pending?domain=sale` | 待核查队列（pending/rejected） | `[{metric_id, metric_cn, metric_en, caliber, diff_summary, ai_by}]` |
| POST | `/api/metrics/{id}/caliber/approve` | 批准，写正式字段 + 触发重评分 | `{metric_id, status:"approved"}` |
| POST | `/api/metrics/{id}/caliber/reject` | 打回，body `{reason}` | `{metric_id, status:"rejected"}` |
| PUT | `/api/metrics/{id}/caliber` | 人工修改（改后 status=edited） | `{metric_id, status:"edited"}` |

**起草响应 `diff_summary` 示例**：`[{field:"caliber_business", models:["gpt-4o","claude-3.5-sonnet"], consensus:"推荐稿", divergent:"qwen-plus 表述不同"}]`

**多模型一致性规则**：`caliber_business` 三模型一致 < 2/3 → `diff_summary` 标记 `high_risk: true`，核查列表置顶。
