# 词根字段与规则（实现基准）

> 状态：已确认，作为 M1 代码与单测的单一事实来源  
> 整合自：`数据治理项目方案_v2.md`、`大模型集成方案.md`、`验收评分标准.md`

---

## 1. 三层数据对象

| 层级 | 用途 | 主要标识字段 |
|------|------|----------------|
| **生成输入** | 业务提交术语 | `cn_term`, `context`, `domain` |
| **模型输出** | 单次 LLM 结果 | `cn_term`, `root_en`, `root_abbr`, `root_type`, `description` |
| **词根库 CSV** | 已入库词根 | `root_id`, `root_cn`, … |

映射：`cn_term`（输入/评审 JSON）= `root_cn`（CSV 列名）。

---

## 2. 词根库 CSV 字段（`roots/{domain}_roots.csv`）

| 字段 | 必填 | 规则 |
|------|------|------|
| `root_id` | 是 | `R_{DOMAIN大写}_{3位序号}`，如 `R_CUST_001` |
| `root_cn` | 是 | 中文词根，同主题域内不可重复（验收） |
| `root_en` | 是 | 标准英文单词，禁止拼音 |
| `root_abbr` | 是 | 用于指标/字段命名，≤6 字符 |
| `domain_code` | 是 | 14 主题域小写代码，如 `cust` |
| `root_type` | 是 | 枚举见下节 |
| `description` | 建议 | 简短说明 |
| `source_model` | 是 | 枚举见下节 |
| `review_status` | 是 | `pending` / `approved` / `rejected` |
| `created_at` | 是 | `YYYY-MM-DD` 或 ISO8601（M1 与方案示例一致即可） |
| `updated_at` | 是 | 同上 |

---

## 3. 枚举与命名规则

### 3.1 `root_type`

`noun` | `verb` | `adj` | `unit` | `time`

### 3.2 `root_abbr`（大模型 Prompt + 验收隐含）

- 长度 ≤ 6
- 长词取前 3–4 字母（如 customer → cust）
- 短词可用全称（如 id, name）
- 多词组合：首字母或缩写拼接（实现 M1：先做长度 + 小写英文字母校验，复杂组合规则 M2 加强）

### 3.3 `source_model`（**文档差异，需你拍板**）

| 值 | 含义 | 出处 |
|----|------|------|
| `model_consensus` | 全模型一致 | 方案 v2、大模型方案 |
| `model_majority` | 多数表决通过 | 大模型方案 §2.4 |
| `manual` | 人工录入/改后确认 | 方案 v2 |
| `model_conflict` | 仅用于评审 JSON 的决策类型，**建议不写入 CSV**，CSV 仍为 `pending` 直至人工改 `approved` | 建议 |

**默认实现（除非你改口）：** CSV 的 `source_model` 使用 `model_consensus` | `model_majority` | `manual`；无法自动决策时不写 CSV，只写 review JSON，`review_status=pending`。

### 3.4 `review_status`

- `approved`：可参与指标命名、验收统计
- `pending`：待人工确认或冲突
- `rejected`：人工驳回，不入库（M1 CLI 可不写 rejected 行）

## 4. 词根生成输入 JSON（`大模型集成方案` §2.1）

```json
{
  "input_type": "root_generation",
  "domain": "cust",
  "terms": [
    {"cn_term": "客户", "context": "…"}
  ]
}
```

---

## 5. 评审记录 JSON（`reviews/root_reviews/…`）

在 §2.5 结构基础上，每条 `items[]` 含：

- `model_results[]`：每模型 `root_en`, `root_abbr`, `root_type`, `description`
- `comparison`：`root_en_consistent`, `root_abbr_consistent`, `root_type_consistent`, `conflict_fields[]`
- `final_decision`：`decision_type` = `model_consensus` | `model_majority` | `model_conflict`
- `auto_approved`：bool，与 `final_decision` + 业务规则一致

---

## 6. 多模型比对与择优（M1 必须实现）

| 比对项 | 权重（文档） | M1 行为 |
|--------|--------------|---------|
| root_en 一致 | 40% | 字段级多数/全一致 |
| root_abbr 一致 | 30% | 同上 |
| root_type 一致 | 10% | 同上 |
| 命名规范度 | 20% | abbr 长度与字符集校验， tie-break 时优先更规范者 |

择优：

1. 全一致 → `model_consensus`, `approved`, `auto_approved=true`
2. ≥2/3 模型在某字段上一致 → 取多数，`model_majority`, `approved`, `auto_approved=true`（文档 §2.4）
3. 无可靠多数 → `model_conflict`, `pending`, `auto_approved=false`
