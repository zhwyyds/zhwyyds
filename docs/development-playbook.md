## §2 根因分类（归纳）

### A. 验证方式错误（最致命，占比最高）
- #4/#10/#11：只用 mock + 同源测试，**从未在"8080 静态页 + 8765 API 分离部署 + 真实 LLM"下跑过** → 用户一用真实环境就爆
- #6/#7/#14/#16：测试只跑 pytest（后端）+ node --check（语法），**从不浏览器实测** → 前端交互 bug 全靠用户截图发现
- #15/#20/#21/#22：改完一个点就收尾，**未做同类问题全量 grep**（重复 id、alert、死代码）

### B. 需求理解不到位（返工最贵）
- #8：用户说"跟查看窗口一样"，前两次做成了弹窗表单/内联行，第三次才对
- 教训：**不自己设计交互，盯着用户指的那个界面抄**

### C. 改动不彻底 / 残留（次致命）
- #12/#13：alert 只改当前文件，不全文搜
- #11/#21/#22：废弃 UI 不删 → id 冲突、死代码
- #14：删字段/列后，手写测试数据不同步

### D. 代码工程问题
- #5：引用未定义变量（无 lint 兜底到运行时才爆）
- #9：IIFE 作用域外追加函数
- #17：badge 语义错配（同名冲突数填到口径治理）
- #19：用 hidden input 冒充"有该功能"

### E. 环境/进程类
- #4：静态服务进程残留 → 502
- #10 根因2：CORS 白名单未覆盖真实部署端口

## §3 每条问题的直接教训

| 问题 | 教训 |
|---|---|
| 分离部署 AI 无效 | **前端改动必须真实跨域环境（分离部署）Playwright 验收**，mock 只能验逻辑不能验连通 |
| 抽屉 ID 冲突 / 重复 id | **HTML id 全局唯一**；废弃 DOM 立刻删除；改动后跑重复 id 审计 |

## §4 强制开发规范（后续所有开发必须遵守）

### 4.1 验证规范（最高优先级）
1. **前端改动 → 必须真实环境 Playwright 验收**：
   ```bash
   .venv/bin/python tests/e2e/test_frontend_smoke.py   # 全功能冒烟（截图 + console + pageerror）
   ```
   - 断言：`pageerror=0`、`console error=0`、`4xx/5xx=0`、点击后 DOM 状态正确
   - 涉及 AI 的功能：真实 DeepSeek 调用验证（不 mock）
2. **分离部署场景**：页面 8080 + API 8765 跨域实测（CORS/API_BASE 探测）
3. **每次提交前**：`pytest + ruff + mypy + 前端 JS 语法 + Playwright 冒烟` 全过才算完成

### 4.2 静态审计规范（改动后必跑）
```bash
# 1. 重复 id 审计（HTML 全局唯一）
grep -oP 'id="[^"]+"' ui-prototype/index.html | sort | uniq -d

# 2. JS 引用 vs HTML id 全集比对（防引用空气）
#    （脚本：收集 getElementById 引用 → 与 HTML id 集合差集）

# 3. 交互类残留全量 grep
grep -rn "alert(" ui-prototype/js/          # 浏览器原生弹窗必须清零
grep -rn "console.log" ui-prototype/js/     # 调试日志清除
```

### 4.3 前端 id 规范
- **HTML id 全局唯一**：同一页面内不得出现重复 id；跨页面也建议唯一（`getElementById` 是全局查找）
- 命名前缀区分：`newMetric*`（新增抽屉）、`metricEdit*`（编辑弹窗）、`nav-badge-*`（侧边栏徽标）
- 同一功能两个入口（如指标库/指标管理）必须用不同 id：`nav-badge-metrics-lib` / `nav-badge-mgmt`

### 4.4 废弃代码规范
- **功能被替代后立即删除旧实现**（旧弹窗、内联行、旧函数、旧导出），不留过渡期
- 删除后跑 §4.2 审计确认无残留引用

### 4.5 交互反馈规范
- **禁止浏览器原生 alert**：全部用页面内提示（toast / 状态栏 / 行内红框）
- 长耗时操作（AI 生成/评审）必须：点击即有"进行中"反馈 + 完成/失败明确提示

### 4.6 数据一致性规范
- 删字段/删列 = 全链路检查：领域模型 → CSV 表头 + 数据 → API schema → 前端表单/表格/展示 → **测试手写行**
- 显示数字必须来自真实数据源（API/已加载数据），禁止硬编码

### 4.7 需求确认规范
- 用户提出界面需求 → **先定位用户指的那个界面/组件**（截图/描述），确认理解后再动手
- 复杂交互（弹窗/抽屉/内联）改动前先给方案让用户确认，不自行设计

### 4.8 提交规范
- 提交信息含：`fix/feat` 前缀 + 问题描述 + 根因 + 验证结果
- 涉及前端：附 Playwright 截图路径或验证输出

### 4.9 Git 分支与发版规范（v0.1.0 起执行）
**采用「双主干」模型：`dev` 承载全部开发代码，`main` 只保留验证通过的功能。不引入 GitFlow 全套（release/hotfix 仅大型团队需要）。**

1. **`dev` = 开发主干（日常开发都在这里）**
   - 所有新功能、修复先在 `dev` 上开发、验证（§4.1 全量验证）
   - 开发走短期分支再合回 `dev`：`feature/xxx` → 验证 → 合并到 `dev` → 删分支
   - CI 对 `dev` 每次 push 自动跑（`ci.yml` 已配置 dev 触发）
2. **`main` = 稳定主干（只进验证通过的功能）**
   - **禁止直推 main**：所有进入 main 的改动必须从 `dev` 通过 PR 合入
   - main 保护（GitHub 已配）：PR + CI 门禁，CI 全绿才可合并
   - `main` 永远可运行，是发布基线
3. **发版流程**：`dev` 验证充分 → PR `dev → main` → CI 全绿 → 合并 → 打 tag
   ```bash
   git tag vX.Y.Z && git push origin vX.Y.Z
   ```
   - 当前基线：`v0.1.0`（06d17e3，测试数据清理后的干净版本）
   - 语义化：v0.2.0 新功能 / v0.2.1 修复
4. **数据纪律**：测试数据（`_N` 编号指标、mock 评审、临时文件）不得混入正式数据文件；发布前按 §5 验收清单确认数据干净

### 4.10 模块化开发与文档存档规范
**任何功能开发必须按模块进行，且每模块一份开发文档（任务清单 + 测试结果），存档于 `docs/modules/`。**

1. **按模块开发**：模块划分见 `docs/modules/模块开发规范.md`（当前 13 个模块，按前端页面划分）
2. **开发前建任务清单**：复制 `docs/modules/_template.md` → 新建 `docs/modules/<module>.md` → 填「任务清单」（每项含验收标准，状态 ☐→🚧→✅）
3. **开发后填测试结果**：pytest / ruff / mypy / JS 语法 + 真实环境 Playwright 验收（pageerror/console/4xx = 0）+ 结论
4. **索引维护**：`docs/modules/README.md` 登记每模块最新状态（✅/🚧/⚠️/📝）
5. **留痕原则**：模块文档就是开发证据——"每个功能当时怎么规划、怎么验证的"都可追溯；变更记录追加在模块文件底部
6. **与分支流程联动**：模块开发在 dev 分支 + `feature/<module>` 子分支 → 测试结果全绿 → PR 合入 main

## §5 验收清单（每次开发完成对照）

```
□ pytest 全绿
□ ruff 全绿（含 --fix）
□ mypy 零错误
□ 前端所有 JS 语法检查通过（node --check）
□ Playwright 真实环境冒烟：pageerror=0 / console error=0 / 4xx=0
□ 涉及 AI 功能：真实 LLM 调用验证通过（非 mock）
□ 分离部署场景：8080 页面 + 8765 API 跨域实测通过
□ HTML 无重复 id
□ JS 无引用空气 id（getElementById 均有对应元素）
□ 无原生 alert 残留
□ 无硬编码假数据（所有数字来自数据源）
□ 废弃代码已删除（无残留引用）
□ 测试数据已清理（不污染用户数据）
□ 已截图保存关键页面（tests/e2e/screenshots/）
□ 改动走 feature/fix 分支 + PR 合并（不直推 main）
□ 双主干模型：开发在 dev，验证通过才 PR 进 main
□ main 保护生效（PR + CI 门禁）
□ 发版打 tag（语义化版本）
□ 模块开发文档已建/更新（docs/modules/<module>.md：任务清单 ✅ + 测试结果 ✅）
```
