# 批量指标导入流水线 需求规格

> 状态：🟢 P1 已完成（H31，2026-08-06）；P2 待启动
> 负责人：数据治理平台
> 关联模块：`metric-mgmt`（指标管理）/ `batch-gen`（批量生成）/ `review`（模型评审）
> 关联文档：`development-playbook.md`（开发规范）、`docs/modules/模块开发规范.md`

---

## 一、背景与目标

**现状痛点**：当前批量生成指标需在 textarea 手动逐条输入 `名称|定义|单位|频率`，大批量（百条以上）时效率极低、无法复用现有指标库、缺乏质量把关环节。

**目标**：建立「CSV 上传 → 待办任务 → 去重 → AI 生成 → 人工评审 → 草稿 → 批量衍生 → 批量 AI 评审 → 发布」的完整批量指标治理流水线，支撑 2000 指标规模的高效治理。

---

## 二、需求明细（5 大模块）

### M1. CSV 切分分组上传（待办任务）
- **输入**：CSV 文件，格式 `metric_cn, caliber_desc`（中文名, 定义），可选扩展列 `unit, frequency, domain_code`
- **切分**：按 **50 条/组** 切分，每组生成一个**待办任务**
- **任务实体**（新增，落盘 `tasks/` 或 `reviews/tasks/`）：
  ```
  任务字段：task_id / batch_id / group_no / total_rows / status
           / dedup_result / generated_count / review_progress / created_at
  任务状态：pending 待处理 → processing 处理中（去重/AI生成）
          → reviewing 人工评审中 → done 已完成
  ```
- **页面**：批量导入页展示任务列表（批次ID/组序号/条数/状态/进度），可点击进入任务详情

### M2. 去重比对（AI 生成前）
- **触发**：任务处理时，先比对指标库再决定是否 AI 生成
- **规则**：
  - 精确匹配：`metric_cn` 与库内已有指标完全一致 → 标记「已存在」
  - 近似匹配：同义词/包含关系命中 → 标记「疑似重复」
- **处理**（用户已确认 B 方案）：重复条目标记「已存在」**留在任务里**，不自动丢弃，由人工勾选确认
- **产出**：`dedup_result = { total, dup, suspect, new }`，只有 `new` 进入 AI 生成

### M3. AI 批量生成指标卡片
- **输入**：去重后的 `new` 条目（中文名 + 定义）
- **输出**：每条目一张指标卡片（复用现有 `suggest` 链路生成 metric_en / 域 / 分类 / 单位 / 频率等）
- **展示**：卡片堆叠列表 + 分页（50 条/组内分页）+ 状态标签（新生成/已存在/疑似重复）

### M4. 逐卡人工评审 → 草稿
- **操作**：每张卡片可「通过 / 打回（可编辑后重提）」
- **通过**：指标状态 → `draft` 草稿（**新增状态**，现有 pending/approved/offline 保留）
- **打回**：卡片标记 rejected，可编辑修正后重新提交人工评审
- **进度**：任务内 `review_progress = 已审/总数`

### M5. 草稿批量衍生 + 批量评审 + 发布
- **批量衍生**：勾选草稿中的**原子指标** → 选修饰词 → 批量生成衍生指标（复用现有 batch-gen 机制，产物也进入草稿）
- **批量 AI 评审**：勾选草稿指标 → 批量发起（用户已确认 B 方案：后台排队 + 进度条 x/100）
- **发布**：评审通过的指标 → `approved` 进入指标库

---

## 三、状态机设计（衔接现有）

```
现有：pending / approved / offline
新增：draft（草稿）、rejected（打回）

批量导入流转：
pending(待处理) → processing(去重+AI生成) → reviewing(人工评审)
  → draft 草稿 → (批量衍生) → draft
  → (批量 AI 评审) → approved 发布 / rejected 打回
```

## 四、分期计划

### 第一期（核心闭环：上传 → 去重 → 生成 → 人工评审 → 草稿）
| # | 任务 | 说明 |
|---|---|---|
| P1-1 | 待办任务实体 + CSV 切分存储 | 后端：tasks 存储 + 切分逻辑 |
| P1-2 | 去重比对 API | 精确 + 近似匹配 |
| P1-3 | AI 批量生成（复用 suggest 链路） | 逐条生成，进度上报 |
| P1-4 | 任务列表页 + 任务详情页 | 前端：任务卡片 + 指标卡片堆叠 + 分页 |
| P1-5 | 逐卡人工评审 → draft | 通过/打回/编辑重提 |
| P1-6 | draft 状态接入现有管理 | 指标管理/评审统计识别 draft |

### 第二期（批量衍生 + 批量评审 + 发布）
| # | 任务 | 说明 |
|---|---|---|
| P2-1 | 草稿批量衍生指标 | 原子×修饰词，复用 batch-gen |
| P2-2 | 批量 AI 评审 + 进度条 | 后台排队 + 进度上报 |
| P2-3 | 发布 approved | 批量发布入口 |

## 五、验收标准

- [ ] CSV 上传 50 条/组切分，任务列表正确生成
- [ ] 去重：库内已有指标被标记「已存在」，不进入 AI 生成
- [ ] AI 生成卡片堆叠展示，新增/已存在/疑似重复标签正确
- [ ] 逐卡人工评审：通过→draft / 打回→rejected 可重提
- [ ] 草稿批量衍生、批量评审进度条、发布全链路可用
- [ ] pytest 全绿 / 真实环境 Playwright 验收 pageerror=0
- [ ] 模块文档 `docs/modules/batch-gen.md` 更新
